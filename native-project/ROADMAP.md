# Native application completion gates

1. **Catalog and editable build baseline:** preserve all originals/recovery
   variants; establish independent modules, dependency hashes, compiler evidence
   and provenance for every source repair.
2. **Source and API completeness:** review missing/additional class names,
   synthetic/anonymous transformations, linkage, decompiler warnings and actual
   method behavior. Continue the 509 pending bounded recovery units; source
   availability and functional completeness are distinct measures.
3. **Linux host integration:** classify every platform-audit candidate. Port
   filesystem, process, service and hardware interactions behind tested adapters.
   Do not blindly change Windows-looking TV payload paths/protocol identifiers.
   Preserve original ports, configurable addresses, licensing identities and
   first-login behavior without resetting upgrade credentials.
4. **Application assembly:** reconstruct WAR resources/manifests/services and
   distribution layouts; add an independently named native package/update
   channel. Never let existing compatibility installers select research JARs.
5. **Offline contracts and simulations:** test archive safety, settings/channel
   maps, EPG, customer-backup compatibility, authentication and protocol messages.
   Keep original inputs and compare outputs, including failure paths.
6. **Isolated Linux runtime/browser:** fresh DB, services, listener checks, login,
   channels/settings editing, clone import/export, SmartCMS workflows, backup,
   restore, upgrade and rollback. No live hotel networking during startup tests.
7. **Approved TV qualification:** identity-pinned target; discover separately
   from enroll. First retrieve clone; writes require explicit execution and the
   allowlist. No automatic production or room-wide testing.
8. **Lower-priority native/RF:** preserve and reconstruct Gateway/DTAPINET,
   TSGen/TsGenUtil, clone packers, legacy platform helpers and RF drivers.
   RF transmission may be unavailable initially; channel-map/EPG support is
   still core scope. Record any unsupported operation explicitly, never silently
   drop a vendor component or report success for a stub.

Current output is a development project, not a working native service release.
